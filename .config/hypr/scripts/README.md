# Hyprland Scripts

## keybinds.py / keybinds-menu.sh

The keybind cheat sheets are generated, not written: `keybinds.py` reads
`keybindings.lua` (plus the volume/lid binds in `hyprland.lua` and your
`custom/keybinds.lua`), `foot.ini`, `~/.tmux.conf` and the Neovim config on
every run. Only the friendly names (`KEY_NAMES`, `AGS_REQUESTS`, `APP_NAMES`,
`SCRIPT_NAMES`) are hand-kept; a bind with no name falls back to its trailing
`-- comment`, so comment new binds.

| Front end | What it shows |
|-----------|---------------|
| `SUPER + /` (`keybinds-menu.sh`) | rofi menu of the desktop keys; Enter runs the selected bind, Esc closes |
| `keys hypr [word]` (fish) | the same table in a terminal |
| `keys [word]` | foot, tmux, fish and Neovim keys |
| `keybinds <tool>` | the above by tool name, plus hand-written sheets for bat / lazygit / yazi |

Section headings come from the `-- ── Name ──` comment rulers in
`keybindings.lua`; the `for` loops (workspaces, resize) and the Right-Alt+W
browser chord are understood as a whole.

## lid-switch.sh

Handles laptop lid open/close events. Monitor names are auto-detected
(`monitor-helpers.sh`: the laptop panel is the `eDP*`/`LVDS*` output, the
external is the first other connected output), so it works on any laptop.

### What it does

**When closing the lid:**
1. With an external monitor: moves every workspace on the laptop panel to the
   external (recording which ones in `$XDG_RUNTIME_DIR/hypr-lid-moved-workspaces`),
   disables the panel, and repositions the external to `0x0` as the primary.
2. Without an external: just blanks the panel (DPMS off).

**When opening the lid:**
1. If the AGS display arranger saved a layout (`custom/displays.lua`) it is
   re-applied as a whole; otherwise the panel is re-enabled at `0x0` and the
   external pushed to its right.
2. Turns the panel on and moves back exactly the workspaces recorded at close.

### Why this approach

The panel is *disabled* (`hypr_monitor "$LAPTOP,disable"`) rather than only
DPMS'd off because:
- Disabling removes the monitor from the layout entirely, allowing the external monitor to use the full coordinate space
- This prevents overlap warnings when the laptop lid reopens
- Moving workspaces before disabling prevents windows from being orphaned

All compositor writes go through `hypr-compat.sh` (`hypr_monitor`, `hypr_dispatch`,
`hypr_eval`), which speaks both config dialects: `hyprctl keyword` only exists
for the old `.conf` config, under the Lua config (0.55+) the same change is an
`hyprctl eval` of an `hl.*` expression.

### Usage

Automatically triggered by Hyprland lid switch events via bindings in `hyprland.lua`:

```lua
hl.bind("switch:on:Lid Switch",  hl.dsp.exec_cmd("~/.config/hypr/scripts/lid-switch.sh close"), { locked = true })
hl.bind("switch:off:Lid Switch", hl.dsp.exec_cmd("~/.config/hypr/scripts/lid-switch.sh open"),  { locked = true })
```

To apply the lid state at login too, see the commented example in
`custom/execs.lua.example`.

### Monitor Configuration

Optional host overrides (set with `hl.env` in the gitignored `custom/env.lua`):
`LAPTOP_SCALE` (panel scale on re-enable; default `auto` = DPI-based) and
`LAPTOP_MODE` (default `preferred`). The monitor layout itself comes from
`custom/monitors.lua` (generated by `gen-host-config.sh`) or `custom/displays.lua`.
